# GD-88 GUI CI results, November 25, 2026

The [release gate](README.md) failed on `feat/gd88-gui` at
`275deaafa836f4715f6cd32b4897e837589b79fc`. One host assertion failed, and two maximal firmware builds exceeded
their application flash regions. The firmware matrix finished with **802 passes and 2 failures across 10 boards**.

## Run scope

The run used `tools/ci.sh` on macOS for the registry, host, bench, Python, license, and similarity stages.
The macOS host run stalled during AddressSanitizer startup in `gfxFbEdgeTest`. The local Linux VM ran the host
suite, a sanitizer attempt, and a `make -k -C tests/host` pass to finish independent tests after the settings failure.
The Linux retries first required the zlib development headers. An early parallel host run emitted a Make jobserver
warning. The keep-going run used serial Make and did not emit that warning.

The firmware stages used the same local Linux VM with Arm GNU Toolchain 13.3.Rel1 and C-SKY GCC 14.2.0.
The native Linux Arm compiler replaced an initial translated compiler that hit an internal error during LTO.
The board groups ran the full matrix without `--quick`. Totals below count each board and configuration once
and exclude setup attempts and scratch builds.

## Failures and scratch verification

- [Settings layout test](../../tests/host/settingsTest.c) expected `reserved11` at byte 406. The GUI branch uses
  byte 406 for `gui_flags` and leaves byte 407 reserved. The same test passed on upstream `main` at
  `39b69c016dac8445d6a42f536314611aed3b7919`. On the GUI branch, a scratch test that asserted both offsets
  passed without any change to the settings structure.
- Both failing maximal builds enabled `CONFIG_UI_PROFILES`. The upstream maximal builds passed with their stack
  checks. Scratch builds on the GUI branch changed only `CONFIG_UI_PROFILES` to `n`. They linked and passed
  their stack checks.

| Board ID | GUI maximal overflow | Upstream maximal free flash | GUI maximal free flash with profiles off |
|---|---:|---:|---:|
| `dm1701` | 15,548 B | 5,112 B | 1,880 B |
| `mduv380` | 16,488 B | 4,148 B | 924 B |

The diagnostic changes were confined to scratch checkouts.

## Skipped or outside the run

- The optional similarity scan was skipped because `RFOUNDRY_SIMILARITY_REFS` was unset.
- The `uv380_family` placeholder was skipped because it has no board makefile.
- The trunking replay test was skipped because `RFOUNDRY_T3_RECORDINGS` was unset. The host SNMP integration
  checks that require system SNMP tools were skipped because those tools were absent.
- HIL cases were collected and their host-side tooling was tested. Hardware and on-air cases were outside
  this run.
